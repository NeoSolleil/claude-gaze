# claude-gaze 構想

Claude Code が「いま何を見ているか」をライブなノード／エッジ図で描くツール。
本書は実装前の構想。事実（公式 docs・実ログ・モックで確認済み）と推定（設計判断・見積もり）を分けて書く。

- 作成: 2026-10-12 ／ 更新: 2026-10-12（P1 実装を反映）
- 状態: P1 実装済み。本書は実装の仕様書として維持する
- 根拠にした Claude Code のバージョン: 2.1.296（実ログ）。docs は code.claude.com/docs/en/ の 2026-10-12 取得分
- UI モック: `mock/index.html`（2D、本命）／ `mock/3d.html`（3D、デモ用の比較版）。架空セッションを再生する単一 HTML で、本物のフックには繋いでいない

## 1. 目的と非目的

### 目的

動作中の Claude Code セッションについて、主体（メインエージェント・サブエージェント）が
どの対象（ファイル・URL・検索クエリ・MCP サーバ・コマンド）を見に行ったかを、
ほぼリアルタイムにグラフで表示する。主体ごとの最新のアクセスを常に光らせ、過去のアクセスは同じ濃さで残す。

利用者はこのツールを自分の Claude Code に導入し（GitHub で公開、Claude Code プラグインとして配布）、
ブラウザで1セッションを選んで眺める。

### 非目的（やらない）

- Claude の挙動のデバッグ支援（無駄読み・見落としの検出）。「見ていない範囲」の表示は対象外
- 静的な依存グラフ（import／call）の解析と重ね合わせ
- 思考の途中経過の表示（ログに無い）
- 「A を読んだから B を見た」という因果の表示（ログには時系列しか無い）
- 複数セッションの同時表示（一覧からの選択のみ）
- 可視化結果の Web 公開（録画・共有機能は対象外）
- 埋め込みモデルや LLM による要約・分類
- ノードの濃さを時間で薄くする表現（モックで試し、読みにくいので廃止）

## 2. データ源と取得項目

### 2.1 主: Hooks（PostToolUse ほか）

公式に契約が定義されており、ファイルパスは絶対パスに正規化済み、サブエージェント内では
`agent_id` / `agent_type` が付く。`"async": true` で本体をブロックしない。

| イベント | 使う項目 | 用途 |
|---|---|---|
| PostToolUse | `session_id` `tool_name` `tool_input` `tool_response` `tool_use_id` `duration_ms` `agent_id` `agent_type` `cwd` `mcp_server` | エッジ生成の主経路 |
| SubagentStart | `agent_id` `agent_type` | 主体ノードの生成 |
| SubagentStop | `agent_id` `agent_transcript_path` | 主体ノードの終了表示 |
| UserPromptSubmit | `session_id` `prompt_id` | ターン境界（画面右上に表示） |
| PostToolUseFailure | PostToolUse と同じ | 失敗した呼び出しも「見に行った」として描く（灰色の点線、イベント行に「失敗」） |
| Stop | `session_id` | メインの「待機中」表示 |
| SessionStart / SessionEnd | `session_id` `cwd` | セッション一覧の出現／消滅 |

各フックは受け取った JSON をそのままローカルサーバへ HTTP POST する（1 行の `curl`。
サーバ未起動時は短いタイムアウトで黙って失敗させ、Claude Code 側には影響させない）。

運用の形: プラグイン導入時に Hooks が一度登録され、以後どのセッションでも通知が飛ぶ。
見たいときにサーバを起動しブラウザを開くと、その時点で動いているセッションを選んで追える。
セッション開始前から見たければ先にサーバを立てておく。スラッシュコマンドはサーバ起動とブラウザを開く入口として用意する（セッションごとに打つものではない）。

既知の制約（事実）:

- `tool_response` の形はツールごとに違い、docs に全ツール分の定義は無い。WebFetch と WebSearch は
  実ログでは本文テキストのみで、構造化結果が無い（§3 参照）
- Hooks 導入前に走ったセッションは拾えない
- PostToolUse はツール失敗時に発火しない。失敗は PostToolUseFailure で受け、存在しないファイルの Read なども描く（実機で確認: 存在しない README.md の Read は PostToolUse に来なかった）

### 2.2 副: セッションログ JSONL（過去セッションの再生用）

`~/.claude/projects/<cwd-slug>/<session-id>.jsonl` とサブエージェント用
`<session-id>/subagents/agent-<agentId>.jsonl`。親子は `agentId` で結べる（実ログで確認）。

公式 docs は「内部形式でどのリリースでも壊れうる」と明記している。したがって
JSONL パーサーは「ベストエフォートの再生機能」と位置づけ、主経路にはしない。
初期段階（§5 の P0・P1）では実装しない。

### 2.3 採らない経路

OpenTelemetry は `file_path` が span 側にしか乗らず、トレーシングの有効化が要る。ローカル用途には重い。

## 3. ノードとエッジの定義（モックで確定）

### 3.1 主体ノード

| 種類 | 生成元 | 表示 |
|---|---|---|
| メインエージェント | `agent_id` 無しのイベント | 六角形。名前 `main` |
| サブエージェント | SubagentStart の `agent_id` | 六角形。`agent_type` を表示。Stop で破線の縁に |

主体ごとに色を割り当てる（6 色、7 体目以降は再利用）。色は線と対象ノードの塗りに使い、「誰が見たか」を表す。
主体ノードの 2 行目に最新の動作（例 `Read src/app.ts`）を出す。待機中・完了のときは 2 行目を出さない。

### 3.2 対象ノード（ツール → 抽出規則）

| ツール | 対象ノード | 抽出元 | 確度 |
|---|---|---|---|
| Read / Edit / Write / MultiEdit / NotebookEdit | ファイル（●） | `tool_input.file_path` | 高（正規化済み） |
| Glob / Grep | ディレクトリ枠（検索範囲） | `tool_input.path`（省略時は `cwd`）。ラベルに pattern | 高 |
| Bash（実在ファイルを参照する） | **ファイルへの破線**。コマンドのノードは作らない | `command` 中のトークンのうち `cwd` 基準で実在するパス。線にコマンド全文、ファイルのラベルに `(cat)` のようにコマンド名 | 低。取りこぼし前提 |
| Bash（ファイル参照なし） | コマンド（タグ形） | `command` の先頭語（npm, git など） | 高 |
| WebFetch | URL（●） | `tool_input.url` | 高 |
| WebSearch | 検索クエリ（◆） | `tool_input.query` | 高 |
| WebSearch | 検索結果 URL | `tool_response` テキスト先頭の `Links: [{title,url}…]` を解析 | 中。テキスト埋め込みで形式変更に弱い |
| `mcp__<server>__<tool>` | MCP サーバ（■） | `mcp_server.name`。ラベルにツール名 | 高 |
| Skill | スキル（■） | `tool_input.skill` | 高 |
| Agent | （主体ノードへ） | SubagentStart と `agent_id` で接続 | 高 |
| ToolSearch / AskUserQuestion / その他 | 描かない | | |

- 対象は **1 ノード**（同じファイル・同じ URL を複数の主体が見ても 1 つ）。塗りは主体の色で、複数の主体が触ったものは色をパイ状に分け、ラベルに `◈n`（n 体が共有）を付ける。縁の色と形が種類を表す
- ファイルは**ディレクトリごとの枠**にまとめ、URL は**ドメインごとの枠**にまとめる。枠自体もノードで、Glob/Grep の検索範囲は枠へのエッジになる
- 検索結果 URL は既定で検索クエリノードの配下に畳み、クリックで展開する。実際に WebFetch された URL は独立ノードとして表に出す

### 3.3 エッジ

- 種類: 主体 → 対象（アクセス）。色は主体の色。Bash 由来の推定は破線
- 属性: 発生時刻、ツール名、`tool_use_id`、`duration_ms`、コマンド全文（Bash）
- 同じ主体・同じ対象の再アクセスは同一エッジの時刻更新と回数加算で表す（多重エッジにしない）
- 主体 → 主体（起動）の線は描かない。系譜は主体一覧に「← main 12s」として出す

### 3.4 「いま」の表現（時間減衰の代替）

- 主体ごとに**最新のイベント 1 件**を常に強調する。対象ノードは太い縁（主体の色）、線は太く、主体ノードは大きく。次のイベントが来たら移る
- 濃さは変えない。過去のアクセスも同じ濃さで残す
- ターン終了（Stop）・サブエージェント終了で、その主体の強調を消す

## 4. 画面と挙動（モックで確定）

### 4.1 構成

```
+----------------+----------------------------------------+------------------+
| セッション一覧 |            グラフ（主領域）             |  詳細            |
| ・live 表示    |  左列: Web（ドメイン枠・検索・コマンド）  |  クリックした    |
| ・cwd / 開始   |  中央: 主体（縦並び）                     |  ノード／線／    |
|                |  右列: ファイル（ディレクトリ枠）         |  イベントの中身  |
| 主体一覧       |  線は直角配線（主体から横に出て、列の     +------------------+
| ・色・系譜     |  間の空白で縦に移動し、対象へ横から入る） |  イベント列      |
| ・live/done    |                                         |  主体タブで絞込  |
+----------------+----------------------------------------+------------------+
| 一時停止 ／ 種類フィルタ ／ Bash経由（推定） ／ 表示: 地図|主体別 ／ 自動で全体表示     |
+----------------------------------------------------------------------------+
```

- 配置は決定的（力学配置ではない）。枠の中は一定間隔の縦リストで、ラベルは外側に出す。文字と線がノードに重ならない
- **表示切替**: 「地図」（1 枚、対象は 1 ノード）と「主体別」（主体ごとの帯に分け、同じ対象は帯ごとに出す）。既定は地図。主体別は読みやすさで劣るので補助
- **主体タブ**: イベント列の上。主体を選ぶと、その主体の線と対象だけ色付きで残り、他は灰色の細線になる（濃さは変えない）。イベント列も同時に絞られる

### 4.2 選択と連動

- ノードをクリック: 詳細（パス／URL、場所、回数、最終時刻、見た主体ごとの回数とツール）。関連するイベント行に印を付けて最新の行までスクロールし、同じイベントで一緒に触られた対象（例: `cat` が見たファイル）を点灯
- 線をクリック: 主体→対象の回数と、ツール呼び出しの一覧（Bash ならコマンド全文）
- イベント行をクリック: 対象ノード・線・主体を点灯して画面を寄せ、Hooks の stdin そのままの JSON を詳細に表示
- 選択は時間で消えない。別のノード／線／行をクリックすると移り、何もない所をクリックすると消える
- 一時停止は**描画だけ**を止める。Claude Code 本体には何もしない。本番では停止中もサーバが通知を溜め、再開時に順に描くか最新へ飛ぶかを選べるようにする
- 「自動で全体表示」: 新しいノードが画面外に出たら全体を収め直す。直前 6 秒に操作したとき、何かを選択中は動かない

### 4.3 3D（見せるモード。実装済み）

表示切替「3D」で 3d-force-graph（three.js）に同じ ops を流す。ディレクトリ／ドメインは灰色のハブで、ファイルが細線でぶら下がって塊になる。粒子が主体から対象へ流れる。軌道型カメラ（左ドラッグ回転・右ドラッグ移動・ホイール）、自動回転あり、ラベルは当たり判定から外す。3D のライブラリは選んだときだけ読み込む（2D だけなら 1.3MB を読まない）。
**主画面は 2D**。3D はラベルの可読性と決定的配置を失うため、記事・デモ向け。

### 4.4 実装構成（P1 時点）

```
src/server/   main.ts（HTTP+SSE+静的配信） hooks.ts（型と検査） store.ts（保持・Bash 推定） sse.ts
src/web/      events.js（Hooks JSON → ops、純関数・テスト済み） model.js（主体・イベント・逆引きの共有状態）
              ui.js（右ペイン・主体一覧・フィルタ） graph2d.js（Cytoscape。地図／主体別・折りたたみ） graph3d.js（3d-force-graph） live.js（SSE・切替・一時停止）
hooks/        hooks.snippet.json（settings.json に写す Hooks 設定）
scripts/      demo-session.sh（架空セッションの投入）
test/         events.test.js（node:test）
```

描画方式はすべて同じ `ops` を受ける。切替時は受信済みイベントの ops を新しい描画器に流し直す（イベント列・選択・タブは保持）。

### 4.5 技術構成（確定）

| 部位 | 決定 | 理由 |
|---|---|---|
| 受信サーバ | Node.js 23.6+ (TypeScript を直接実行)、`node:http` のみ、HTTP POST 受信 + SSE 配信、メモリ保持 | 依存最小。ビルド工程なし。DB なし |
| フロント | 素の ES Modules（フレームワークなし） | モックの描画コードで要件を満たせた。React は不要と判断 |
| グラフ描画 | **Cytoscape.js**（複合ノードで枠、taxi 配線、preset 配置） | 必要な表現がすべて実現できた |
| 3D | 3d-force-graph + three + three-spritetext（選択時のみ読込） | 実装済み |
| 配布 | Claude Code プラグイン（hooks 定義 + サーバ起動コマンドを同梱） | 導入が `claude plugin` 1 回で済む（P2） |

プラグインに hooks を同梱する際のマニフェスト形式は未確認。P2 の着手時に docs で確認する。

### 4.6 性能の前提（事実）

- 実機計測: セッションログの tool_result 時刻とサーバ受信時刻の差は 4〜5 ms（Read 4、Bash 4、WebFetch 5）
- 1 セッションのノード数は、検索結果を展開すると数分で 200〜300 に達する（サブエージェント 1 体で WebSearch 16 回、WebFetch 23 回の実績）。畳み込みが既定なのはこのため
- 色で区別できる主体は 5〜6 体まで。それ以上は主体タブでの絞り込みが前提

## 5. 段階的な進め方と見積もり

見積もりは推定。モックで UI の試行錯誤は済んでいるので、P0 の見積もりは当初より下げた。

| 段階 | 内容 | 完了条件 | 見積もり |
|---|---|---|---|
| モック | UI の決定（本書 §3・§4） | 済（2026-10-12） | 済 |
| P0 | 受信サーバ + SSE + 描画（1 セッション、ファイル／URL／主体色／「いま」） | 済（2026-10-12）。遅延 4〜5 ms | 済 |
| P1 | サブエージェント、検索結果の畳み込み、MCP／Skill、Bash 推定、失敗した呼び出し、主体タブ、地図／主体別、枠の折りたたみ、3D | 済（2026-10-12）。Bash 推定: 過去ログ 45 件中 15 件で実在ファイルを検出、未検出 30 件の大半は起動・curl・rm などファイルを読まないコマンド | 済 |
| P2 | プラグイン化、README、導入手順、Qiita 記事の素材（スクショ・GIF）。3D の同梱可否 | 別マシンで `claude plugin` から導入して動く | 6〜10 時間 |
| P3（任意） | JSONL からの過去セッション再生 | Hooks 導入前のセッションを選んで再生できる | 未見積もり。形式依存のため着手判断は P2 後 |

### リスク

- Hooks の `tool_response` 形式がツールごとに未定義。WebSearch の結果 URL 抽出はバージョンで壊れうる。壊れたらクエリノードだけ残る設計にする
- Bash 由来のファイル参照は実ログでツール呼び出しの過半を占める。推定の精度がそのまま見え方を左右する。P1 で実装し、精度を実ログで測る
- ディレクトリ枠は対象が増えると縦に長くなる。P1 で枠の折りたたみ（ディレクトリ単位で畳む）を入れる
- 公開後は他人の環境で動く。サーバ未起動・ポート衝突・Windows のパス形式は P2 で扱う
